## 이커머스 구매 전환 대시보드

온라인 쇼핑몰의 실제 행동 로그 275만 건으로 "방문자는 어디서 이탈하는가"를 분석했습니다.

**데이터**: [RetailRocket recommender system dataset](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset)
(Roman Zykov / Retail Rocket, 라이선스 CC BY-NC-SA 4.0) · 2015-05-03 ~ 2015-09-18 (139일)

### 주요 결과

- 조회 → 장바구니 2.63%, 장바구니 → 구매 32.39%, **조회 → 구매 0.85%**
- 방문 빈도별 구매 전환율: 1회 0.01% / 2-5회 1.49% / 6-20회 9.42% / **21회+ 25.74%**
- 방문자당 이벤트 수의 **중앙값은 1건**. 방문자의 71%가 한 번 보고 떠나며, 그 집단은 사실상 아무도 사지 않는다

이 쇼핑몰의 병목은 구매 단계가 아니라 **첫 방문자를 재방문으로 데려오지 못하는 지점**입니다.

### 심화 분석

**세션** (30분 무활동 기준으로 방문 분리) — 총 1,754,593개, 방문자당 1.25개. 세션당 이벤트 중앙값 1건,
세션 길이 중앙값 0분. **첫 방문에서의 구매 발생률은 0.53%, 10번째 이상 방문에서는 4.81%로 9배** 차이.

**구매 리드타임** — 구매자의 **66.0%가 첫 방문 1시간 이내에 구매**. 구매 전 조회 수 중앙값 2건.
오래 비교하는 형태가 아니라 즉시 결정형이며, 장기 리타게팅보다 첫 방문 경험이 중요하다는 뜻.

**코호트 리텐션** — 1주 뒤 재방문율이 초기 4.8%에서 후반 2.2%로 하락. 신규 유입은 매주 6~8만 명으로
일정한데 재방문율만 떨어지는 중이며, 구매가 재방문에 크게 의존하므로 매출에 직접 연결되는 악화 신호.

**품절과 이탈** (재고 변경 이력 150만 건을 시점 정합으로 조인) — 재고 있는 상품은 조회의 4.57%가
장바구니로 가지만 품절 상품은 0.46%로 **10배 차이**. 반면 **일단 담긴 뒤에는 품절 상품의 구매 전환율이
34.35%로 재고 있는 상품(30.36%)보다 오히려 높았다.** 품절은 담기 전에 걸러지며, 담을 만큼 원한 상품이면
재입고를 기다려서라도 산다는 뜻. (당초 가설은 "품절이라 못 사고 이탈한다"였고, 기각됨)

**요일** — 수요일 1.010%로 최고, 토요일 0.615%로 최저. 주말은 조회가 주는 것보다 구매가 더 크게 준다.

**집중도** — 조회는 상위 1% 상품이 22.67%를 가져가지만 구매는 같은 상위 1%가 10.05%.
**구매가 조회보다 덜 집중**되어 있어 롱테일의 매출 기여가 크다. 조회된 상품 233,091개 중
구매까지 간 것은 12,025개.

**카테고리** — 조회 5,000건 이상인 128개 카테고리 중 상위는 전환율 4.37%로 전체 평균의 5배.

### 이상 트래픽 제거

데이터 제공자는 이런 로그에 최대 40%의 비정상 트래픽이 섞일 수 있다고 밝혔습니다. 직접 규칙을 세워 찾아봤습니다.

**채택**: 조회 100건 이상 · 장바구니 0회 · 구매 0회 → 132명(이벤트의 0.97%) 제거

**탈락한 규칙 4개와 이유**:

| 규칙 | 결과 | 탈락 이유 |
|---|---|---|
| 이벤트 47건 이상(상위 0.1%) | 1,413명 | 제거하니 구매가 34% 사라짐. 상위 활동층은 우량 고객이었다 |
| 평균 이벤트 간격 1초 미만 | 11명 | 4.5개월에 걸친 활동이라 평균 간격이 희석됨 |
| 상위 0.1% & 구매 0건 | 893명 | 장바구니 전환율이 오히려 하락. 담고 안 산 고객은 이탈 분석 대상 |
| 카테고리 다양성 상위 | — | 가설과 반대. 조회 100건+ 구매자는 평균 113.7개 카테고리, 무행동자는 32.1개 |

네 번 모두 "활동량 많은 집단 = 우량 고객"이 나왔습니다. 결론은 **events.csv만으로는 볼륨 기반 규칙이
1% 남짓까지가 한계이며, 이벤트를 1건만 남긴 봇은 정상 방문자와 구분할 수 없다**는 것입니다.

## 파일 구성

```
index.html              자기소개 페이지 (GitHub Pages 루트)
dashboard/              아파트 대시보드 빌드 산출물
ecommerce/              이커머스 대시보드 빌드 산출물
app/                    아파트 대시보드 소스 (Vite + React + TypeScript)
app-ecom/               이커머스 대시보드 소스
scripts/
  build_ecom_data.py    이벤트 로그 집계 → 대시보드용 JSON 4개
  explore_visitors.py   방문자별 분포 탐색, 규칙 후보 1차 검증
  compare_rules.py      규칙 후보별 적발 규모와 지표 변화 비교
  build_item_map.py     item_properties zip → 상품별 카테고리/재고 맵
  explore_category.py   카테고리 다양성이 이상 신호인지 검증
data/                   원본 CSV (용량이 커서 커밋하지 않음)
```

## 다시 만들려면

1. [Kaggle 데이터셋](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset)에서 `events.csv`를
   받아 `data/events.csv`에 둡니다
2. 집계: `py -3 scripts/build_ecom_data.py`
3. 빌드: `npm --prefix app-ecom install && npm --prefix app-ecom run build`

카테고리 분석까지 재현하려면 `item_properties_part1/2.csv.zip`을 받아 `scripts/build_item_map.py`의
경로를 맞춘 뒤 실행합니다. 압축을 풀 필요는 없습니다.

## 알려진 한계

- **방문자-일 중복 집계** — 날짜별 집계라 여러 날 방문한 사람은 날짜마다 세어집니다. 순 방문자 수는 전체 기간
  값만 정확합니다
- **버킷 소속 고정** — 방문 빈도 집단은 전체 기간 기준으로 한 번 정해지며, 기간 필터로 바뀌지 않습니다
- **시각은 UTC** — 원본에 사용자 지역 정보가 없어 현지 시각으로 변환할 수 없습니다
- **이상 트래픽 완전 제거 불가** — 위 표 참고
